# ギルド記録

作業対象Projectの `.chat-orchestrator/` を管理する。OrchestratorのサンドボックスではProjectのルートは `/workspace`。記録は元ファイルに保存され、ユーザーがGuild Boardの **Sync** を押すと画面へ反映される。

## 作成・更新の進め方

- 最初に既存の `overview.md`、`tasks.md` と今回に関連する日誌を読む。依頼された事実・作業結果・既存記録を根拠に更新し、期限・担当・完了・意思決定を推測で補わない。
- 初期登録を依頼されたら、専用フォルダと不足する `overview.md`、`tasks.md` を作る。情報がない項目は未記録・未定とし、架空のTODOや実績を作らない。既存ファイルはテンプレートで上書きしない。説明や相談だけならファイルを作らない。
- 更新では依頼に関係する箇所だけを変更する。TODOの状態、現在地、次の一手に食い違いが残らないようにする。作業が終わっていても、ユーザーの確認が必要なら「確認待ち」に置く。
- 日誌は依頼された作業結果・会議の決定事項・根拠となるファイルへの相対パスを短く残す。同じ出来事の訂正なら既存の記録を修正し、重複する日誌を増やさない。依頼に関係しない過去ログやTODOは保持する。
- 完了時に変更したファイルと主な更新を伝え、Guild BoardでSyncするよう案内する。ShellからアプリのAPIへ接続したり、画面の更新が済んだと報告したりしない。

## ファイル形式

UTF-8の通常ファイルを使用する。専用フォルダや記録がシンボリックリンクの場合は追跡して編集しない。

```text
/workspace/.chat-orchestrator/
├── overview.md
├── tasks.md
└── activity/
    └── YYYY-MM-DD-01.md
```

### overview.md

```markdown
# プロジェクト名

## 現在地
確認できた進捗、成果、未解決の点を簡潔に記す。

## 次の一手
次に行う作業や必要な判断を具体的に記す。
```

各節の先頭600文字までがカードに表示されるため、重要な内容を先に書く。画面のProject名はアプリの登録名であり、この見出しを書き換えても変更されない。

### tasks.md

```markdown
# TODO

## 未着手

## 進行中

## 確認待ち

## 待ち

## 保留

## 完了
```

タスクは該当する節の下に1行で `- [ ] タスク名` と書く。期限が明示されている場合だけ、末尾に `(due: YYYY-MM-DD)` を付ける。会話で確定した日付を使い、相対日付は会話のタイムゾーンに合わせる。日付を確定できない場合は期限を付けず、その旨を伝える。

| 見出し | 用途 |
| --- | --- |
| 未着手 | まだ始めていない作業 |
| 進行中 | 着手していて、実施中の作業 |
| 確認待ち | ユーザー自身の確認・判断が必要 |
| 待ち | 他者の回答、データ、外部条件などを待つ |
| 保留 | 意図的にいったん止めている作業 |
| 完了 | 完了が確認できた作業。`- [x]` を使う |

既存の英語見出し `Todo` / `In progress` / `Review` / `Waiting` / `Paused` / `Done` もそのまま使える。状態を変えるときは同じタスクを該当節へ移し、二重登録しない。完了を取り消すときは「完了」節から移動し、チェックも `[ ]` に戻す。「完了」節に残すと未チェックでも完了扱いになる。

Project全体の状態は「確認待ち → 進行中 → 待ち → 未着手 → 保留 → 完了」の優先順でアプリが計算する。状態フィールドや達成率を別途書く必要はない。実際の状況に合う節を選ぶ。

### activity/*.md

1ファイルを1件の記録とし、先頭に `# 記録のタイトル`、その下に事実・決定事項・未解決事項を書く。本文の先頭300文字がプレビューになる。日付はファイル名の先頭 `YYYY-MM-DD` が使われる。実際の出来事の日付を使い、同日に複数記録する場合は `YYYY-MM-DD-01.md`、`YYYY-MM-DD-02.md` のように未使用の番号を選ぶ。過去ログのファイル名は今回の更新日に変更しない。

## 保存前の確認

- `overview.md` と `tasks.md` は専用フォルダ直下、日誌は `activity/` 直下に置く。コードフェンス内のチェックボックスはTODOに取り込まれない。
- 各ファイルは64 KiB以内、取り込み対象の合計は512 KiB以内、TODOは完了済みを含め500件以内。長い成果物の本文はProject内の別ファイルへ保存し、記録には概要と参照だけを残す。既存記録が上限に達した場合は勝手に削除せず、整理が必要な範囲を伝える。
- 日誌はファイル名の降順で30件まで取り込まれる。古い日誌を消す必要はない。`activity/` が2000エントリを超えるとSyncできないため、その場合は整理を提案する。
- 編集後に内容を読み直し、期限が実在する日付か、完了と未完了が矛盾していないか、今回と無関係な記録を失っていないかを確認する。
