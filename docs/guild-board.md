# Guild Boardの記録形式

登録済みProjectの直下に `.chat-orchestrator/` がある場合だけ、ギルド掲示板のSync対象になります。フォルダを削除・リネームすると、次回Syncで一覧から外れます。掲示板のSync処理はこのフォルダを作成・編集しません。作成手順はモデルのsystem promptに追加していません。

標準で利用できる同梱Skill [guild-journal](../backend/app/bundled_skills/guild-journal/SKILL.md)に、チャットから記録の作成・更新を依頼できます。`runtime.toml`への追加登録は不要です。たとえば「このProjectをギルドに登録して」「比較実験が終わったのでギルドのTODOと作業日誌を更新して」と依頼します。`@guild-journal` または＋メニューの「ギルド記録」で明示指定もできます。Skillがファイルを保存した後、ユーザーがSyncして表示へ取り込みます。Skillがあるだけで全Projectにフォルダを作ったり、毎回の作業を自動記録したりはしません。

```text
プロジェクト/
└── .chat-orchestrator/
    ├── overview.md
    ├── tasks.md
    └── activity/
        ├── 2026-10-09.md
        └── 2026-10-10-mtg.md
```

UTF-8のMarkdownを使用します。LLMによる推測や要約はせず、以下の形式を読み取ります。画面は閲覧用で、TODOの完了・修正などは元ファイル側で行ってからSyncしてください。

## overview.md：現在地と次の一手

```markdown
# 研究プロジェクト

## 現在地
比較実験が完了。条件Aで精度が改善した。結果のレビューを待っている。

## 次の一手
追加実験の比較条件を決める。
```

「現在地」は `概要` / `Summary` / `Status`、「次の一手」は `次にやること` / `Next` / `Next action` でも認識します。現在地の見出しがない場合は本文を使います。カードには各600文字までを取り込み、全文は詳細画面の原文で読めます。プロジェクト名はアプリの登録名を使用します。

## tasks.md：クエスト帳

```markdown
# TODO

## 未着手
- [ ] 比較実験の計画を書く

## 進行中
- [ ] 分析結果を整理する

## 確認待ち
- [ ] 追加実験の条件を決める (due: 2026-10-16)

## 待ち
- [ ] 共同研究者からデータを受け取る

## 保留
- [ ] 別モデルでの検証

## 完了
- [x] 初回実験を実施する
```

- 1行の `- [ ] タスク名` を1件として読みます。通常の文章やコードフェンス内の例はTODOにしません。
- 状態は見出しから読み取ります。`Todo` / `In progress` / `Review` / `Waiting` / `Paused` / `Done` も使えます。見出しなしは「未着手」です。
- `[x]` / `[X]`、または「完了」節にある項目は完了扱いです。完了節から戻すときは見出しとチェックの両方を更新してください。
- 期限は任意の `(due: YYYY-MM-DD)` です。担当者やその他の補足はタスク名に含められます。
- プロジェクトの状態は「確認待ち → 進行中 → 待ち → 未着手 → 保留 → 完了」の順で、存在する状態を表示します。TODOがない場合は「記録待ち」です。プロジェクトの達成率は推測しません。
- 「確認待ち」にはユーザー自身の確認・判断が必要な項目を置きます。「待ち」には他者からの回答などを置きます。
- 詳細では完了済みを初期状態で折り畳み、原文のファイル名・行番号を表示します。

## activity/*.md：冒険日誌

```markdown
# 比較実験のレビューMTG

条件Aを採用する方針に決定。追加実験は条件Bを比較対象にする。
提出日は10月16日。次回までに分析結果を整理する。
```

1ファイルを1件の記録として、最初の見出し（なければ最初の空でない行）をタイトル、本文の先頭300文字をプレビューにします。日付はファイル名先頭の `YYYY-MM-DD` から読みます。日付なしのファイル名ではファイル更新日時（UTC）の日付を使用します。同日の複数記録は `2026-10-09-01.md` のように区別できます。全文はプロジェクト詳細から読めます。

## Syncと表示の範囲

- 掲示板を開くと、アプリのSQLiteに保存した最後のスナップショットを表示します。初回も自動Syncはしません。
- Syncで登録済みProjectの専用フォルダだけを読み直します。ファイルの常時監視、ポーリング、モデル呼び出しは行いません。
- `overview.md` / `tasks.md` がない場合もプロジェクトを表示し、お知らせを出します。`activity/` は任意です。それ以外のファイル・入れ子のディレクトリは読みません。
- 「記録更新」は取り込んだファイルの最新更新日時、「取得」はそのプロジェクトの最後の成功日時、「最終Sync」は全体の最後の取り込み処理の日時です。画面上の日時はブラウザのタイムゾーンで表示します。
- 一部プロジェクトを読めなくても、ほかのプロジェクトのSyncは続けます。取得失敗したプロジェクトは前回の記録と取得失敗表示を残します。登録解除したプロジェクトの古い記録は表示しません。
- 各ファイル64 KiB、1プロジェクトの記録合計512 KiB、TODOは500件までです。超過・不正なUTF-8・不正な期限・読み取りエラーの場合は、そのプロジェクトの前回の記録を保持します。
- 冒険日誌はファイル名の降順で30ファイルまでを取り込み、それより古い記録はファイルに残ります。`activity/` が2000エントリを超える場合は取得失敗になります。画面の日誌は8件ずつ、TODOは30件ずつ追加表示します。
- シンボリックリンクや通常ファイル以外の記録は読み込みません。
- 管理画面から「プロジェクトのチャットへ」で直近の会話を開けます。会話がない場合は新規チャットを作成します。

API: `GET /api/guild` は保存済みスナップショット、`POST /api/guild/sync` は手動取り込みです。

## 表示とアニメーション

画面のラベル・状態・エラーは英語、部屋のキャラクターの吹き出しは日本語です。プロジェクト名と記録本文は元の言語のまま表示します。日本語・英語の見出しは引き続き両方読み取れます。画面全体の色と書体は他の画面に揃え、ギルドの雰囲気は小さな部屋と紋章に残しています。

ヘッダーの小さなギルドの部屋はインラインSVGと段階的なCSSアニメーションで描画します。ブラウザの現地時刻に合わせ、朝（05–11時）は準備、昼（11–17時）は配達、夕方（17–20時）はゆっくり巡回、夜（20–翌05時）はお茶と休息に変わります。窓の景色や部屋の明るさも変わります。時間帯の境界に1回だけタイマーを設定し、画面に戻った際も時刻を確認します。

日本語の短いコメントは時間帯ごとに用意した文章です。CSSアニメーションの40秒ごとの区切りで次のコメントへ進み、吹き出しをクリックしても切り替わります。AI生成やプロジェクト状態の推測はしません。ゲームエンジン、追加画像、JavaScriptのフレームループ、追加API呼び出しは使用しません。画面外や非表示タブでは動き・コメント切替・時間帯タイマーを停止し、画面を離れると破棄します。Pause / Resumeで動きと自動コメント切替を止められ、設定はブラウザに保存されます。OSの「動きを減らす」設定にも従います。停止中も時間帯は更新し、吹き出しの手動切替は利用できます。
